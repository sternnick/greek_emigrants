# Πολύγλωσσα Μεταδεδομένα (COAR)

[🇬🇧 English](multilingual-metadata.md)

Οι συστάσεις της COAR για αποθετήρια που διαχειρίζονται πολύγλωσσο και μη
αγγλικό περιεχόμενο ([σελίδα πηγής](https://coar-repositories.org/what-we-do/multilingual-and-non-english-content/),
πρόσβαση 2026-10-05) ζητούν το αποθετήριο:

> Declare the language of the resource at the item level · Declare the language of
> the metadata (e.g. `xml:lang`) · Use standard (two-letter or three-letter)
> language codes (ISO 639) · Enable UTF-8 support and use the original alphabet /
> the writing system whenever possible · If it is necessary to transliterate
> metadata, use recognized standards · Include keywords in many languages ·
> Ensure that language codes can consistently be used across the repository
> collection.

Η παράθεση μένει στα Αγγλικά επί λέξει: είναι η ίδια η σύσταση, όχι το περιεχόμενό
μας — οι παραθέσεις δεν μεταφράζονται (από τη σύσταση #2 στο AGENTS).

Πώς καλύπτεται το καθένα, και πού επιβάλλεται.

## Πού μένουν οι κωδικοί

| ανάγκη | πεδίο | σύστημα κωδικών | επιβολή |
|---|---|---|---|
| γλώσσα της πηγής | `language` (αρχείο πηγής) | ISO 639-1 | `source.schema.json` + `check_language_codes()` |
| η ίδια γλώσσα για μεταδεδομένα αποθετηρίου | `language_iso639_2b` | ISO 639-2/B | ο ίδιος έλεγχος — το ζεύγος πρέπει να συμφωνεί |
| γλώσσα μιας παράθεσης | `evidence[].quote_language` | ISO 639-1 ή -2/B | `check_quote_languages()` |
| γλώσσες του dataset | μπλοκ metadata στο README, `i18n/languages.json` | και τα δύο | `tests/test_coar.py` |
| πεδίο για άνθρωπο | αντικείμενο `{el, en}` | τα κλειδιά *είναι* οι ετικέτες | `check_bilingual_fields()` |

Το `i18n/languages.json` είναι το μόνο σημείο όπου γράφεται ζεύγος κωδικών.
Τίποτα άλλο στο αποθετήριο δεν κρατά πίνακα γλωσσών, οπότε καμία πηγή δεν μπορεί να
ισχυριστεί `el`/`fra`.

**Γιατί δύο συστήματα.** Το ISO 639-1 είναι αυτό που βλέπουν άνθρωποι και ονόματα
αρχείων (`summary.el.md`)· το ISO 639-2/B είναι ο βιβλιογραφικός κωδικό που
εκθέτουν το λογισμικό αποθετηρίου και το OAI-PMH. Το `language` τροφοδοτεί
αναφορές και τους κανόνες παραθέσεων· το `language_iso639_2b` τροφοδοτεί τα
μεταδεδομένα του αποθετηρίου. Το `scripts/i18n.py` μετατρέπει και προς τις δύο
κατευθύνσεις (`to_iso639_2b`, `to_iso639_1`) και το
`scripts/migrate_language_codes.py` γράφει τον κωδικό -2/B από τον -1, ώστε να μη
μπορούν να αποκλίνουν στο χέρι.

## Αρχικό σύγγραμμα, όχι μεταγραφοποίηση

Οι παραθέσεις αποθηκεύονται **με το αλφάβητο της πηγής**: πίνακας OΟΣΑ/ONS στα
Αγγλικά, INSTAT στα Αγγλικά, πίνακας Destatis στα Γερμανικά
(`quote_language: de`), κυβερνητική δήλωση στα Ελληνικά. Καμία μεταγραφοποίηση δεν
γίνεται πουθενά στα δεδομένα — το μοναδικό ASCII μέσα σε ελληνική πρόταση είναι
οι τεχνικοί όροι (`source_ref`, `null`). Μια μηχαναγνώσιμη συμβολοσειρά πρέπει να
είναι ASCII για να είναι αναζητήσιμη και σταθερή στα diffs· γι' αυτό τα IDs, τα
enums και τα ονόματα αρχείων είναι αγγλικά (AGENTS.md), ενώ ό,τι διαβάζει άνθρωπος
και κάθε παράθεση κρατά το δικό του σύγγραμμα.

## Σύσταση COAR → υλοποίηση

| σύσταση | σε αυτό το dataset |
|---|---|
| δήλωση γλώσσας ανά πόρο | κάθε `sources/**/*.yaml` έχει `language` **και** `language_iso639_2b`· κάθε παράθεση έχει `quote_language` |
| δήλωση γλώσσας μεταδεδομένων | το μπλοκ στο README δηλώνει `inLanguage: ["eng","ell"]`· τα δίγλωσσα πεδία ομαδοποιούνται ανά γλώσσα αντί να στηρίζονται σε ιδιότητα |
| τυποποιημένοι κωδικοί ISO 639 | και τα δύο συστήματα, από ένα μητρώο, με έλεγχο στο commit |
| UTF-8 + αρχικό αλφάβητο | κάθε αρχείο UTF-8· παραθέσεις στο αρχικό σύγγραμμα (οι ελληνικές μένουν σε ελληνικούς χαρακτήρες) |
| μεταγραφοποίηση μόνο με πρότυπα | δεν μεταγραφοποιούμε κείμενο· μόνο οι αναγνωριστικοί τίτλοι είναι ASCII, κατά σύμβαση, και η σύμβαση τεκμηριώνεται εδώ |
| λέξεις-κλειδιά σε πολλές γλώσσες | το μπλοκ metadata έχει `keywords` σε `en` και `el` |
| συνεπείς κωδικοί σε όλη τη συλλογή | το `validate.py` απορρίπτει μη εγγεγραμμένο κωδικό ή εκτός συστοιχίας ζεύγος· το `migrate_language_codes.py --check` αποδεικνύει ότι κανένα αρχείο δεν απέκλινε |

## Προσθήκη γλώσσας

Τέσσερα βήματα, και τα tests σου λένε αν παρέλειψες κάποιο:

1. `i18n/languages.json` — μία εγγραφή: `iso639_1`, `iso639_2b`, `name_native`,
   `name_en`, `direction`, `script`, `report_suffix`, `ui`.
2. `i18n/<code>.json` — strings διεπαφής, με το ίδιο σύνολο κλειδιών με τα υπόλοιπα
   (το `tests/test_i18n.py` συγκρίνει σύνολα κλειδιών, όχι πληθάριθμο).
3. `i18n/<code>.md` — το στατικό κείμενο μεθοδολογίας/αδείας.
4. Κάθε δίγλωσσο πεδίο `{…}` παίρνει το νέο κλειδί. Δεν υπάρχει script μετανάστευσης
   για αυτό το βήμα και δεν υποκρύπτεται ότι υπάρχει: ο έλεγχος του `validate.py`
   (`check_bilingual_fields()`) απορρίπτει κάθε δίγλωσσο πεδίο στο οποίο λείπει
   κλειδί, οπότε τα κενά καταγράφονται αρχείο-αρχείο μέχρι να συμπληρωθούν.
   Εργαλείο είναι το `python scripts/validate.py`.

Οι αναφορές παίρνουν τη νέα γλώσσα αυτόματα: τα `scripts/report.py` και
`scripts/report_flows.py` διαβάζουν `i18n.ui_langs()` και ονοματίζουν τα αρχεία
μέσω `i18n.report_suffix()`, οπότε καμία αναφορά δεν κρατάσκληροκωδικοποιημένη λίστα γλωσσών.

Τα migrations που υπάρχουν όντως είναι τα `scripts/migrate_sources_v2.py`
(ανεξαρτησία και blocks δημοσίευσης) και `scripts/migrate_language_codes.py`
(κωδικός ISO 639-2/B)· και τα δύο δέχονται `--check` και τρέχουν από το
pre-commit hook.
